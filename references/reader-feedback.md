# 读者反馈复盘（Reader Feedback Loop）

> SKILL.md P4.5 配套参考。网文是数据驱动的连载——追读率、章评、订阅是唯一可靠的"效果"信号。LLM judge 判不了"爽不爽"，读者数据能。
> 目标：把读者反应翻译成可执行的创作调整，而不是"读者说不好就重写"。

## 1. 数据录入（每卷一次，或用户要求时）

用户提供以下任一数据，AI 录入 `追踪/复盘.md`：

| 数据源 | 示例 | 用途 |
|--------|------|------|
| 追读率曲线 | Ch10 追读 92% → Ch15 82% | 定位流失点 |
| 章评要点 | "打脸不够爽""这段水" | 定位失败模式 |
| 收藏/订阅变化 | 大高潮后订阅 +8% | 验证爽点有效性 |
| 用户自评 | "这卷节奏太慢" | 直接调整信号 |

## 2. 复盘流程（P4.5）

```
1. 读取 追踪/复盘.md 历史 + 用户提供的新数据
2. 逐章标记：
   - 哪些章追读下降 → 查节奏图谱 / 失败模式表 §1
   - 哪些爽点读者买账（章评热 / 追读持平）→ 在 payoffs.jsonl 对应条目标 reader_hit
   - 哪些角色/对白被点名 → 更新角色档案/文风样本（作者批准后）
3. 产出调整建议（不自动执行）：
   - 节奏调整：拉近/推远下一高潮
   - 细纲调整：砍支线 / 提主线 / 提前回收某钩子
   - 人设调整：角色标签强化或弱化
4. 展示给用户，用户确认后改 大纲/节奏图谱/细纲
```

## 3. 决策规则

| 信号 | 动作 |
|------|------|
| 连续 3 章追读下降 | 下一章必出爽点/推进项，砍低价值支线 |
| 某类爽点 reader_hit 高 | 同结构爽点可复用（换皮不换骨），在爽点账本标记 |
| 某角色出场章追读上升 | 该角色加戏，登记配角池"受欢迎"标记 |
| 章评集中骂"水" | 跑失败模式 #1/#7，压缩中段 |
| 大高潮后订阅涨 | 记录为"该类型高潮有效"，节奏图谱备注 |

## 4. 复盘模板（`追踪/复盘.md`）

```md
# 读者反馈复盘

## 本卷数据
- 卷：{卷号}
- 追读曲线：{章号: 追读率, ...}
- 章评高频词：{...}
- 订阅/收藏变化：{...}

## 买账的爽点（reader_hit）
| 章 | 爽点 | 读者反应 | 复用价值 |
|----|------|---------|---------|

## 流失点诊断
| 章 | 流失信号 | 失败模式 | 调整动作 |
|----|---------|---------|---------|

## 待用户确认的调整
1. {调整建议}
2. {调整建议}
```

## 5. 注意

- **复盘不改正文正典**：调整只作用于 大纲/节奏图谱/细纲/人设标签；已归档正文不动（除非用户明确要求）。
- **数据不足时**：无追读数据则只做"章评要点复盘"，并标注 `无数据`。
- **防过度反应**：单一负面章评 ≠ 失败信号；至少 2 个独立信号才触发调整。
