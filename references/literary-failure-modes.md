# 文学失败模式（Literary Failure Modes）

> SKILL.md P3.5 / P4 / P4.5 的兜底参考。工程层 fallback（预算超限、脚本失败、canon_patch）见 SKILL.md「异常与边界条件」；本节只解决**文学层**失败——AI 写得"没错"但"不好"。
> 结构采用 darwin-skill 的三段式：**触发条件 / 一线修复 / 仍失败兜底**。每条都是网文实战里的真实翻车点。

## 1. 三段式失败模式表

| # | 触发条件 | 一线修复 | 仍失败兜底 |
|---|---------|---------|-----------|
| 1 | 用户说"这章没意思" / "水" | 跑爽点诊断：期待感是否设置未兑现？冲突是否变软？人物是否有动机？钩子是否空转？ | 回 P2.7 重拆场景卡，删除无推进场景 |
| 2 | 连续 3 章爽点只设不收（`payoffs.jsonl` 待兑现堆积） | 本章强制兑现 1 个旧期待感，删减新期待感 | 降级节奏图谱，把大高潮提前或改写细纲 |
| 3 | 反派行为与自身利益/智商矛盾（降智） | 重写该场景，给反派一个说得通的动机或信息差 | 标记「建议 canon_patch」交 P4 用户决定，绝不硬改 |
| 4 | 打脸不响（装逼铺垫足够但读者无快感） | 检查被打脸方是否先赢过面子/先占了便宜——打脸要"先给后夺" | 补充一个"旧账回响"细节再收束 |
| 5 | 主角人设飘（做出违背底线的行为） | 对照角色档案「绝不会说/不可违背底线」，重写该行为 | 若行为合理则 canon_patch 更新人设底线并记 change_log |
| 6 | 金手指破格（主角依赖金手指解决一切，期待感失效） | 检查 `panels.jsonl` 规则，给金手指设限或代价 | 增加金手指的消耗/冷却/暴露风险约束 |
| 7 | 节奏拖（连续静场超 800 字 / 连续 2 章无推进） | 按 `节奏图谱` 找出拖点，压缩中段，提前冲突 | 拆分章节，把拖的后半段挪到下一章 |
| 8 | 战斗戏水（无战术/无代价/无反转） | 检查越级规则：越级是否付了代价？敌人是否有底牌？ | 给敌人一个反转底牌，或让主角赢得不轻松 |
| 9 | 情感戏突兀（上章冷战下章亲密） | 查 `relationships.jsonl` sentiment 跳跃值 | 补一个过渡桥段（动作承载，见 style-and-pacing §6b） |
| 10 | 章节无有效推进（字数达标但信息密度=0） | 对照 P3 出口标准：推进项/钩子/爽点至少满足一项 | 重写该章核心事件，删功能重复段落 |
| 11 | 读者反馈"看不懂/人太多" | 检查出场角色数量、专有名词密度 | 加角色身份锚点（称号+动作），砍无用配角 |
| 12 | 主角长期被压、无爽点反馈 | 查 `节奏图谱` 爽点列，连续 N 章无兑现则本卷欠账 | 卷末安排集中兑现章 |

## 2. 网文失败模式黑名单（dim9：写作时不要做的事）

| # | 反模式 | 为什么不要做 | 替代做法 |
|---|---|---|---|
| 1 | 反派持续降智 | 读者最恨"作者强行让反派犯蠢" | 反派有正当动机 + 信息差 + 合理错误 |
| 2 | 水字数拖剧情 | 追读率暴跌的直接原因 | 每章必有推进项（P3 出口标准） |
| 3 | 主角开挂无代价 | 金手指破格 = 期待感归零 | 面板规则 + 越级代价（见 canon-tracking） |
| 4 | 打脸只打一次就忘 | 没有"旧账回响"的爽点是一次性的 | 爽点账本记录被打脸方，后续可复现 |
| 5 | 配角用完即弃 | 读者记住配角，作者忘了配角 | 配角池登记出场频率与弧线 |
| 6 | 战斗只看数字 | 数值碾压无戏剧张力 | 战术/环境/情报差/代价 > 单纯数值 |
| 7 | 情感直给不承载 | "她感到感动"式直告 | 动作承载（多盛一碗饭） |
| 8 | 设定倾倒 | 开局一堆专有名词劝退 | 设定按需释放，黄金三章零倾倒 |

## 3. 用户负面反馈诊断决策树

```
用户反馈
├── "没意思 / 水 / 拖"          → 失败模式 #1/#7/#10 → 查推进项 + 节奏图谱
├── "主角太弱 / 憋屈"           → 失败模式 #12 → 查爽点账本欠账
├── "反派太蠢"                  → 失败模式 #3 → 重写动机
├── "看不下去 / 弃了"           → 开篇问题 → 跑黄金三章检查（validate.sh --opening）
├── "人物都不记得谁是谁"        → 失败模式 #11 → 砍配角 + 加身份锚点
├── "打脸不够爽"                → 失败模式 #4 → 加"先给后夺"回响
└── "设定前后对不上"            → 正典问题 → 跑 validate.sh --canon / canon_patch
```

## 4. P3.5 文学审稿自检（写后必过一遍）

- [ ] 本章至少一个期待感被推进或兑现（查 `payoffs.jsonl`）
- [ ] 出场反派/配角行为与动机一致（无降智）
- [ ] 本章有效推进项 ≥ 配置值（信息/关系/战力/爽点任一）
- [ ] 金手指使用遵守面板规则（`panels.jsonl` immutable）
- [ ] 主角人设底线未被打破
- [ ] 结尾钩子 ≠ 上一章结尾钩子（承接但推进）
