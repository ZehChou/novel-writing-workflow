# 类型化模板（Genre Profiles）

> SKILL.md P2.6 / P2.7 配套参考。不同网文类型的节奏、爽点频率、对白占比完全不同。开书初始化时按题材选择一种 profile，覆盖默认节奏参数，写入 `project-config.md`。
> 这是 README「轻小说专项优化」的实际落地——不只轻小说，所有主流类型都有一份参数表。

## 1. Profile 选择

开书初始化（P0）时，从 `project-config.md` 题材判断类型，将对应参数写入配置：

| Profile | 适用题材 | 识别关键词 |
|---------|---------|-----------|
| 男频爽文 | 玄幻/都市/无敌流/系统流/赘婿 | 打脸、升级、装逼、金手指 |
| 轻小说日常 | なろう系/异世界/日常系/校园 | 吐槽、萌、日常、角色互动 |
| 悬疑无限流 | 无限流/恐怖/解密/权谋 | 谜题、规则、反转、信息差 |
| 女频言情 | 现言/古言/重生宅斗 | 感情线、误会、拉扯、苏点 |

## 2. 参数表

| 参数 | 男频爽文 | 轻小说日常 | 悬疑无限流 | 女频言情 |
|------|---------|-----------|-----------|---------|
| 单章钩子密度 | ≥2 个 | 1 个 + 角色互动钩 | ≥2 个 + 规则悬念 | 1-2 个情感钩 |
| 爽点/期待感频率 | 每 2-3 章一个闭环 | 每 3-4 章一个情感高潮 | 每 2 章一个谜题推进 | 每 3 章一个情感推进 |
| 对白占比 | 40-55% | ≥50% | 30-45% | 50-65% |
| 日常/非日常比 | 3:7 | 7:3 | 2:8 | 5:5 |
| 静场上限 | ≤800 字 | ≤600 字 | ≤500 字 | ≤800 字 |
| 五感侧重 | 视/触（战斗） | 视/听（互动） | 视/嗅（氛围） | 视/触（情感） |
| 最强支柱维度 | 战力+爽点账本 | 对白+关系弧 | 谜题+信息差 | 关系+情感递进 |

## 3. 轻小说专项（对话驱动）

README 承诺的「对话驱动叙事」落地规则：

- **对白占比 ≥50%**：P3.5 机械校验增加对白占比检查（`grep` 引号行 ÷ 总段数）。
- **吐槽式内心独白（ツッコミ）**：吐槽必须来自人物立场与信息差，禁止复读弹幕、禁止解释笑点。
- **日常与非日常交替 7:3**：日常章不承担爽点义务，专注角色关系与萌点积累；非日常章集中推进。
- **萌要素与角色标签化**：角色标签（如"面无表情的毒舌""天然呆"）必须建立在行为一致上，禁止只贴标签不演出。
- **节奏**：每章一个"角色互动记忆点"，卷内大高潮以情感爆发或关系转折为主，不靠战力。

## 4. 男频爽文专项（期待感与爽点）

- **打脸结构**：先给（对方先赢面子/占便宜）→ 蓄力（主角隐忍收集信息）→ 夺（公开打脸）→ 余韵（旧账回响）。爽点账本记录"被打脸方"，后续可复现。
- **金手指节奏**：金手指每 N 章展示一次新能力（N 由 `panels.jsonl` 配置），展示必带限制或代价。
- **升级反馈**：突破章节必须给读者可视反馈（身体变化/周围人反应/旧敌震惊），不只在面板数字上变。

## 5. 悬疑无限流专项（谜题与信息差）

- 每章至少一个规则/线索推进，谜题层按 `mysteries.jsonl` 释放，**主角知道的绝不能比读者多**。
- 反派智商：反派必须掌握主角不知道的信息（信息差），禁止"主角轻松看穿一切"。
- 反转：每个反转必须能在前文找到可回查的线索（否则是"作者钦定"）。

## 6. 女频言情专项（感情线与拉扯）

- 感情线按 `relationships.jsonl` 弧线渐进，禁止"一见钟情直接定情"。
- 拉扯（推拉）必须有合理动机：身份/误会/旧伤/顾虑，禁止为拉扯而拉扯。
- 苏点：主角光环必须带代价或短板，否则沦为玛丽苏/杰克苏。

## 7. Profile 变更

连载中途可换 Profile（如日常文转战斗文），需在 `project-config.md` 标注变更章号，并重新审视 `节奏图谱` 与 `爽点账本` 欠账。
